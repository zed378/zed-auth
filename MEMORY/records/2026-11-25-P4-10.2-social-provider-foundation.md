# P4-10.2 - Social provider and state foundation

**Date**: 2026-11-25. **Status**: REVIEW; parent P4-10 remains WIP.

Implements steps 2-4 of [the feature spec](../../TASKS/specs/P4-10-social-login-federation.md), under ADR-028 and ADR-030. Plan references: `docs/PLAN/02-REQUIREMENTS.md` FR-3, `docs/PLAN/05-API-CONTRACT.md` social login, `docs/PLAN/08-AUTHORIZATION.md` Part B, and `docs/PLAN/11-TESTING.md`.

## Implemented boundary

- Optional Google, Microsoft, and GitHub configuration uses existing `file:`/`env:` secret references. Secrets resolve only during exchange, errors are generic, and reference fields are excluded from JSON. Disabled providers require no credentials or network access.
- Callbacks derive from an HTTPS issuer origin and the exact provider callback path. Userinfo, queries (including an empty `?`), fragments (including an empty `#`), encoded alternate paths, and partial configuration are refused.
- Redis stores ten-minute state using SET NX and redeems it with atomic GETDEL. Independent random state, PKCE S256 verifier, and OIDC nonce bind the attempt to the server's organization, provider, intent, pending request, callback, and browser token. Link intent additionally binds the authenticated user and session; it does not implement linking.
- Only a digest of that binding is persisted. Redis keys hash the opaque state. The verifier never appears in the authorization URL, and the browser token is removed from returned transactions. Binding mismatches spend the attempt; expiry, corruption, storage outages, and concurrent replay fail closed.
- OIDC validates RS256 signatures against bounded, cached JWKS plus issuer, audience, authorized party, expiry, issue time, not-before, subject, and nonce. Discovery must confirm the pinned issuer and supported endpoints; metadata cannot supply another token or key-fetch destination. Refresh attempts are throttled, and expired keys are not reused during an outage.
- Google requires `email_verified`. Microsoft uses a configured, canonical, nonzero tenant UUID, exact issuer and `tid`; its email fields are not identity evidence. Wildcard Microsoft tenants are unsupported because the storage key has no issuer column.
- GitHub uses its OAuth code exchange and authenticated profile/email APIs. A positive numeric account ID is the subject, and at least one valid verified email is required. Email never becomes the returned identity key.
- Provider requests use HTTPS, TLS 1.2 or newer, timeouts, bounded response bodies, and no redirects. The adapters neither query nor create local users and never retain provider tokens in the identity result.

## Remaining integration

P4-10.3 must bind these primitives to the hosted start/callback handlers, re-read organization policy, resolve only existing linked users, enforce account status/MFA, issue the existing session, write audit events, apply per-provider rate limits, and expose the hosted provider buttons. P4-11 remains responsible for authenticated linking/unlinking.

No hosted endpoint, Management API capability, OpenAPI contract, generated client, public feature claim, deployment, or commit is introduced by this foundation. The feature cannot yet be used to sign in. Disable the optional configuration to roll back; the additive P4-10.1 identity table can remain.
