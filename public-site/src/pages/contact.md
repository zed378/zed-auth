# Contact

## Security issues {#security}

**If you have found a security issue, report it to <security@zedth.my.id>.**

This is the documented channel for responsible disclosure, and it exists because a
researcher with nowhere to report goes public instead — which helps nobody, least of
all the people running the software.

What helps a report get fixed quickly:

- What you did, in enough detail to reproduce it.
- What you expected, and what happened instead.
- Any affected version, URL, or account identifier — but **not** credentials or
  personal data belonging to anyone else.

Please give us a reasonable window to fix and ship before publishing. We will confirm
receipt, tell you what we found, and let you know when it is fixed. If you would like
credit in the changelog, say so and we will include it.

**Please do not** run automated scanners against the hosted environments, attempt
denial of service, or access data belonging to another account. Testing against your
own deployment is welcome and encouraged.

## Everything else

For integration questions, bug reports that are not security issues, or anything about
the project's direction, open an issue at
[github.com/zed378/zed-auth/issues](https://github.com/zed378/zed-auth/issues).

Discussion in the open is preferred where it is possible: the answer to an integration
question is usually useful to whoever asks it next, and an issue thread is findable in
a way that an email reply is not.
