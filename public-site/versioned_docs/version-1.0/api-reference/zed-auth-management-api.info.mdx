The Management REST API for the Zed Auth service.

**Every capability in the management console is available here.** The
console is a client of this API and has no privileged path around it
(`PLAN/02` FR-14). If the console can do something this API cannot, that is
a defect.

## Current status

Phase 0. The service runs, and the endpoints below are the ones that exist:
operational probes only. The identity and authorization endpoints arrive in
Phase 1 and are deliberately absent from this document until they are real.

## Versioning

Management endpoints are prefixed `/v1`. Breaking changes go to `/v2` with a
published deprecation window for `/v1` (`PLAN/05` Part B). The operational
probes are unversioned: they describe the process, not the API.

## Authentication

Management endpoints require an OAuth 2.0 Bearer access token, including
the Client Credentials grant for service accounts. Authorization is
enforced server-side on every request without exception — the console
hiding a control is a user-experience decision, never a security one
(`PLAN/08`).
